# Audit remediation — November 2, 2026

The six findings in [the fork audit](FORK-AUDIT-2026-11-02.md) are addressed in source. These changes follow immutable v1.0.0; its published assets are unchanged and do not contain these fixes. No new release is published by this change.

| Finding | Change | Verification |
|---|---|---|
| F1: language reload bypasses stale-save protection | Same-profile, same-path view reloads retain the original source snapshot; actual file opens and successful writes still establish their own baselines. | New Windows MainViewModel regression and a local production-source harness reject external changes after view reload. |
| F2: untrusted allocation counts | Summary generations, property collections, audio chunks, and related table/map allocations validate counts against remaining bytes and practical limits before allocation. Collection metadata and bulk reservations share a per-stream allocation budget. | Bounded invalid generation/collection fixtures reject negative and excessive counts before allocation. |
| F3: backward property parsing | Negative sizes are rejected; export, object, and property scopes bound reads/seeks. Explicit object end limits are respected; property count, nesting, and forward progress are bounded. | Negative, excessive, undersized, and cross-export payload fixtures fail; a valid IntProperty/None fixture still parses. Test streams enforce an operation limit. |
| F4: duplicate metadata loss | Item copies preserve Cloned, Modified, TimesModified, and nested enchantment InvestedPoints. Placement fields remain intentionally omitted. | A fully populated item round trip compares every serialized field except placement and checks nested copy independence. |
| F5: startup preload hangs | Startup awaits the actual preload worker task, so failures reach the existing error dialog and limited-feature fallback. | Independent control-flow review; temporary harness extracted the updated production method and verified both exception propagation and successful completion with UI stubs. Interactive WPF fallback remains a manual check. |
| F6: nested apphost provenance exemption | Only exact root-relative MCDSaveEdit.exe receives the SDK apphost exemption. | A nested same-name executable fails origin validation; the valid root apphost remains accepted. |

Integrated local verification: 35 portable production-source safety tests and 32 Python validator/release tests passed without skips, including actual signed NuGet integrity checks. The full Windows/native hosted validation remains the authoritative platform gate for each pushed commit.

Parser allocation budgets are defensive limits for supported local content, not a guarantee of bounded total process memory under every input. Real installed-game PAK compatibility, manual gameplay/console/Wine checks, and exhaustive fuzzing remain outside this remediation. Repository master protection is left to the maintainer as requested.
